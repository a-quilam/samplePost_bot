# Poster: правила работы

Правила дополняют задание этапа и не отменяют требования к безопасности
данных, тестам и CI.

## Контекст и исследование

- Один этап — одна новая сессия. Не продолжай сессию предыдущего этапа.
- Начинай с краткого задания и нужных разделов
  `Poster/docs/stage18_architecture.md`; не изучай проект целиком.
- Читай только файлы, необходимые для задания. Для поиска используй
  `grep`/`glob`, большие файлы читай фрагментами (`offset`/`limit`).
- Не перечитывай неизменившиеся файлы и не повторяй уже выполненное
  исследование кода.

## Проверки и вывод

- Во время работы запускай только целевые тесты затронутого сценария.
- Перед завершением — один полный прогон
  `make check PYTHON=.venv/bin/python` (он же `make accept`). Не запускай
  `check` и `accept` дважды без изменений в коде.
- Успешный вывод тестов не вставляй целиком: достаточно итоговой строки.
  При ошибке показывай минимальный релевантный фрагмент или хвост лога.
- Не скрывай и не подавляй падения, пропуски и предупреждения проверок.
- Не ослабляй существующие тесты, проверки безопасности и CI.

## Границы и данные

- Меняй бизнес-логику только в рамках явно выданного задания этапа.
- Не изменяй и не удаляй реальную `Poster/post_bot.db`, `.env` и секреты.
- Заверши работу после зелёных проверок и краткого отчёта. Следующий этап
  начинай только по отдельному заданию.
