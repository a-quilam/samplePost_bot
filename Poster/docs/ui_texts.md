# Тексты интерфейса: один YAML для владельца

Все пользовательские тексты основных экранов Poster (меню, справка,
конструктор анонса, календарь, места и площадки, кирпичики, шаблоны,
администрирование, ошибки и всплывающие ответы) собраны в одном файле.
Владелец передаёт его редактору, получает исправленную версию, кладёт
обратно и перезапускает службу — Python-код при этом не меняется
(Poster 2.2 U4a, дефект №10; полнота каталога — Poster 2.3 H4).

Вне каталога остались только технические строки (журнал, исключения для
разработчика) — см. «Что осталось намеренно».

## Где лежит

| Что | Путь |
| --- | --- |
| Каталог текстов | `Poster/config/ui_texts.yaml` |
| Загрузчик и проверка | `Poster/utils/ui_texts.py` |
| Документация | `Poster/docs/ui_texts.md` (этот файл) |

Путь можно переопределить переменной окружения `UI_TEXTS_PATH` — это нужно
тестам и нестандартным развёртываниям, для обычной работы не требуется.

## Как редактировать

1. Откройте `config/ui_texts.yaml` любым текстовым редактором (кодировка
   UTF-8).
2. Меняйте **только значения** после двоеточия. Ключи в кавычках слева от
   двоеточия не переименовывайте и не удаляйте: по ним код находит строку.
3. Строки с `#` в начале — комментарии, их можно дополнять.
4. Проверьте файл (см. «Проверка»), затем перезапустите бота.

## Формат строк

- Значение — строка в двойных кавычках **в одну строку**. Перенос строки
  внутри значения записывается как `\n` (обратная косая черта и `n`), как в
  `"первая строка\n\nвторая строка"`. Именно так выглядят абзацы.
- `{имя}` — переменная, которую подставляет код: например `{place}`,
  `{step}`, `{total}`, `{value}`, `{brick}`, `{limit}`, `{photos}`,
  `{count}`, `{query}`, `{name}`. **Набор переменных в строке менять нельзя**:
  проверка сравнит его с вшитым дефолтом и признает файл невалидным.
  Меняйте только текст вокруг `{...}`.
- Значения, которые подставляет код (названия мест, введённый текст,
  названия кирпичиков, описания), **экранируются**: `<`, `>`, `&`, `"`, `'`
  останутся видимым текстом и не станут разметкой Telegram.
- **Telegram-разметка** (`<b>`, `<i>`, `<code>`, `<a href=…>`) допустима
  только в строках, чей ключ заканчивается на `_html` (например
  `help.text_html`, `wizard.question.description_html`,
  `admin.conflict.notification_html`). В остальных строках теги будут
  показаны пользователю как обычный текст.

## Проверка

Из каталога `Poster`:

```bash
.venv/bin/python -m utils.ui_texts
```

Команда печатает строку вида
`ui_texts: ok, source=yaml, keys=1092, errors=0, warnings=0, path=…`
и возвращает код 0. Если есть ошибки — код 1 и список причин.

Что проверяется: синтаксис YAML, что значения — строки, что присутствуют
обязательные ключи (`menu.main`, `menu.manage`, `help.text_html`) и что
набор переменных `{...}` в каждой строке совпадает с дефолтом.
Предупреждения (`WARNING`) не блокируют запуск: так отмечаются ключи, которых
нет в файле (для них берётся вшитый дефолт) и лишние ключи, которые код не
читает.

## Применение

Каталог читается один раз при старте процесса. После правки файла
перезапустите службу:

```bash
systemctl --user restart poster-bot
```

Горячего перезапуска по изменению файла нет намеренно: правка применяется
целиком и предсказуемо. Для явной перезагрузки в коде есть
`utils.ui_texts.reload_texts()`.

## Если в файле ошибка

Бот **не запускается с половиной каталога**:

- при синтаксической ошибке, неверном типе значения, пропаже обязательного
  ключа или изменённом наборе переменных файл считается невалидным целиком;
- файл сохранён не в UTF-8 (типичный «ANSI» редактора) или обрезан
  посередине символа — тоже невалидный каталог: кодировка должна быть
  UTF-8, иначе каталог не читается вовсе;
- в лог пишется `CRITICAL` с путём файла и причиной;
- бот продолжает работать на вшитых дефолтах (`utils.ui_texts.DEFAULTS`),
  то есть остаётся живым и предсказуемым, а правки не применяются;
- исправьте файл по сообщению в логе, проверьте командой выше и
  перезапустите службу.

Посмотреть причину последней загрузки в работающем процессе можно через
`utils.ui_texts.last_report()`.

## Изменения Poster 2.3 (этап H3)

Экран правки готового анонса больше не предлагает «Применить изменения»:
сохранённое значение сразу заменяет доставленную версию. Поэтому из каталога
удалены ключи:

- `buttons.finished.apply` («🔄 Применить изменения») — кнопки нет ни на
  одном экране;
- `buttons.finished.extras` («➕ Кирпичики ({count})») — счётчик заменён
  входом `buttons.finished.extras_edit`.

Новые ключи:

| Ключ | Где | Что содержит |
| --- | --- | --- |
| `wizard.extras.title` | список доп. полей готового анонса | заголовок «🧱 Дополнительные поля» |
| `wizard.extras.intro` | там же | объяснение: меняется только этот анонс, правки применяются сразу |
| `wizard.extras.empty` | там же | пустое состояние «Дополнительных полей пока нет.» |
| `buttons.extras.add` | там же | «➕ Добавить поле» |
| `buttons.extras.edit` | там же | «✏️ {number}. {title}» — вход в правку поля |
| `buttons.extras.delete` | там же | «🗑 {number}» — удаление поля |

Правило то же, что и для остальных строк: меняются только значения,
`{number}` и `{title}` в `buttons.extras.edit` переименовывать нельзя.

### «Текущее значение» (требование D)

Сохранённые значения на экранах шаблонов и мест показывает общий компонент
`Poster/utils/current_value.py`: подпись, линия-разделитель, значение,
линия-разделитель. Значение выводится с сохранённой разметкой, без `<code>`
и без «косметической» обрезки. Единственный предел — физический лимит
Telegram: если значение не влезает, показывается начало и явная пометка
«… Показано начало значения: экран Telegram ограничен 4096 символами, полное
значение сохранено.» Полное значение всегда остаётся в базе и в анонсе.

Пометка о лимите и пустое значение живут в каталоге
(`templates.clip.soobschenie_sokrascheno`, `templates.value_block.*`):
это видимый пользователю текст, и владелец меняет его через YAML.

### Изменения Poster 2.3 (этап H4): полный каталог

На каталог переведены подписи, которые раньше оставались литералами:
разделы администрирования (`handlers/admin.py`), кирпичиков
(`handlers/bricks.py`), шаблонов (`handlers/templates.py`), сообщения
валидации ввода (плашки «Адрес уже такой», «Число слишком велико» и т. п.),
сообщения об ошибках правки места, подписи календаря
(`utils/calendar_view.py`) и всплывающие ответы (`alerts.*`).

Каталог вырос со 154 до 1092 ключей. Ключи следуют конвенции
`раздел.экран.фрагмент`; суффикс `_html` по-прежнему означает доверенную
разметку.

## Что осталось намеренно

Вне каталога остались строки, которые **не являются текстом экрана**:

- журнал (`logging.*`) и сообщения исключений для разработчика:
  `bot.py` — «TELEGRAM_BOT_TOKEN не задан — см. .env.example» (сообщение
  старта, до появления интерфейса), `utils/tg_context.py` — «В update нет
  callback_query/сообщения/пользователя/чата»;
- `utils/screen.py` — служебные записи журнала о неудачной правке/отправке
  сообщения; пользователь их не видит;
- `utils/keyboard_layouts.py` и `handlers/places.py` — программные
  `ValueError`/`RuntimeError` о нарушении контракта вызывающего кода
  («per_row должен быть положительным», «У нового места нет канонического
  названия»);
- `handlers/wizard_questions.py` — `ValueError("Лимит видимого текста
  должен быть положительным")`: это проверка аргумента внутренней функции,
  а не сообщение пользователю (оставлено с комментарием в коде);
- шаблоны анонсов (`template_types.py`, BUILTIN) — это публикуемый текст,
  а не интерфейс;
- значения кирпичиков, коды и `callback_data` — технические данные;
- шутки интерфейса (`utils/ui_humor.py`) — отдельный управляемый набор,
  включается флагом `UI_HUMOR_ENABLED`;
- разбор дат словами (`utils/parsers.py`: «января», «понедельник»,
  «через неделю») — это входной язык распознавания, а не подпись экрана.

## Для разработчика

- Новая строка: добавьте ключ в `DEFAULTS` (`utils/ui_texts.py`), затем ту же
  строку в `config/ui_texts.yaml` в подходящий раздел; в коде используйте
  `tr("ключ", **переменные)`.
- Разметка — только суффикс `_html` в имени ключа. Значение, уже прошедшее
  allow-list (`stored_value_html`), подставляется через `tr_safe`: повторное
  экранирование испортило бы сохранённое форматирование.
- Тесты: `tests/test_poster2_u4a_texts.py` (разработчик) и
  `tests/test_poster2_u4a_texts_tester.py` (независимые проверки).
