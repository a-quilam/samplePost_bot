# Команда агентов Poster

Постоянная команда OpenCode V2 для проекта Poster. Конфигурация — файлы в
`.opencode/agents/`.

Команда работает **автономно**: обычная разработка, тесты, коммиты и обычный
`git push` не требуют подтверждений. Заблокировано только то, что может
испортить данные или репозиторий.

## Состав и модели

| Агент | Mode | Модель | Роль | Права |
| --- | --- | --- | --- | --- |
| `poster-manager` | primary | `routerai/z-ai/glm-5.3-flash` | декомпозиция, делегирование, интеграция, приёмка, отчётность | читает код и diff, запускает проверки; правит только `Poster/docs/agent_team/*`; вызывает четырёх подагентов; `git add`/`commit`/`push` |
| `poster-architect` | subagent | `routerai/z-ai/glm-5.3-flash` | исследование архитектуры и рекомендации | только чтение, без правок, коммитов и shell-записи |
| `poster-developer` | subagent | `routerai/deepseek/deepseek-v4.1-flash-1017` | реализация по заданию менеджера, регрессионные тесты, исправление дефектов | правит исходники, миграции и тесты в границах задания; `git add`/`commit`; push делает менеджер |
| `poster-tester` | subagent | `routerai/deepseek/deepseek-v4.1-flash-1017` | независимая проверка результата, тесты через FakeBot и временные SQLite | правит только `Poster/tests/*`; запускает проверки; без коммитов |
| `poster-reviewer` | subagent | `routerai/z-ai/glm-5.3-flash` | независимая проверка реализации, безопасности и регрессий | только чтение и проверки; исправления предлагает |

Модели назначены после проверки RouterAI: `z-ai/glm-5.3-flash` отвечает через
уже настроенный ключ и корректно вызывает инструменты в OpenCode V2.
Разработчик и тестировщик остаются на DeepSeek V4.1 Flash: им нужен длинный
бюджет шагов и точная работа с кодом.

**`steps` у менеджера отсутствует.** Ограничение шагов задаётся только у
подагентов: разработчик — `steps: 80`, остальные — по `steps: 60`. Менеджер
работает без искусственного лимита: он делегирует, а не программирует.

## Разделение ролей

| Работа | manager | architect | developer | tester | reviewer |
| --- | --- | --- | --- | --- | --- |
| Исходники, миграции | deny | deny | allow | deny | deny |
| Тесты | deny | deny | allow | allow | deny |
| Документы `Poster/docs/agent_team/` | allow | deny | по заданию | deny | deny |
| Чтение кода, `git diff` | allow | allow | allow | allow | allow |
| Запуск проверок | allow | нет (не его работа) | allow | allow | allow |
| `git add` / `git commit` | allow | deny | allow | deny | deny |
| `git push` | allow | deny | deny | deny | deny |
| Вызов подагентов | 4 роли | deny | deny | deny | deny |

Менеджер **не пишет код**: `edit` разрешён только в
`Poster/docs/agent_team/`, а запись через shell закрыта отдельными правилами
(редиректы, `tee`, `sed -i`, `cp`/`mv`/`rm`, heredoc, инлайн-скрипты).
Если тесты падают, менеджер ставит задачу `poster-developer`.

## Разрешения

По умолчанию разрешено всё, что нужно для обычной разработки:

- чтение и поиск по проекту (`read`, `glob`, `grep`) — без подтверждений;
- shell для проверок и git, включая составные команды
  (`cd Poster && make check …`, конвейеры, `&&`, `;`) — без подтверждений;
- целевые тесты и `make check` / `make accept`;
- форматирование (`make format`, `black`, `ruff`) — у разработчика;
  у менеджера, тестировщика, ревизора и архитектора запрещено, потому что
  переписывает исходники.

Git по ролям:

| Операция | manager | developer | tester | reviewer | architect |
| --- | --- | --- | --- | --- | --- |
| `git add` / `git commit` | allow | allow | deny | deny | deny |
| `git push` | allow | deny | deny | deny | deny |
| `git push --force*`, `git reset --hard`, `git clean` | deny | deny | deny | deny | deny |

Подагенты не могут вызывать других подагентов: у каждого стоит
`subagent * → deny`, глубина подагентов в OpenCode по умолчанию равна 1.

## Что защищено

- **Секреты**: `.env`, `.env.*`, `secrets/`, ключи (`*.key`, `*.pem`,
  `*.p12`, `id_rsa`, `id_ed25519`) нельзя прочитать, изменить или вывести
  через shell. `.env.example` разрешён — это безопасный образец.
- **Реальная база**: `Poster/post_bot.db` и `*.db*` нельзя прочитать,
  изменить, скопировать или удалить; `backups/` тоже защищён.
- **Работающий бот**: `make run`, `python bot.py`, `botctl.sh start|stop|restart`
  и запросы к `api.telegram.org` запрещены — тестовые сообщения реальным
  пользователям не уходят.
- **Разрушительный Git**: force push во всех видах, `reset --hard`,
  `git clean`, `filter-branch`, `update-ref`, `branch -D`, `git restore`
  запрещены.
- **Система и чужие каталоги**: `sudo`, `rm -rf /`, `rm -rf ~`, `mkfs`,
  `dd`, `diskutil`, `shutdown` запрещены; `external_directory` разрешён
  только для временных каталогов (`/tmp`, `/private/var/folders`).
- **Правила команды**: `AGENTS.md`, `opencode.jsonc` и `.opencode/**` агенты
  не переписывают — их утверждает владелец.

## Роли «только чтение»

У `poster-architect` и `poster-reviewer` shell разрешён целиком, поэтому
запись через него закрыта отдельными правилами: редиректы (`>`, `>>`),
`tee`, `touch`, `mkdir`, `cp`, `mv`, `ln`, `chmod`, `chown`, `truncate`,
`sed -i`, `patch`, `git apply`, `rm`, `python -c`, heredoc (`<<`) и
конвейер в интерпретатор.

## Процедура работы менеджера

1. Определить ближайший незавершённый этап.
2. Делегировать реализацию `poster-developer`.
3. Получить результат и проверить diff.
4. Делегировать независимые тесты `poster-tester`.
5. Делегировать ревизию `poster-reviewer`.
6. При дефектах вернуть конкретное задание разработчику.
7. Повторить проверки.
8. Принять этап, зафиксировать состояние в
   `Poster/docs/agent_team/state.md`, сделать commit/push/CI.
9. Перейти к следующему этапу.

Менеджер не читает тысячи строк кода без конкретной необходимости и не
программирует сам. Подагентам передаются краткие самостоятельные задания с
точными границами и ожидаемым результатом.

## Как выбрать менеджера

- В TUI/приложении: `Ctrl+P` → список агентов, либо `<leader>a`
  (по умолчанию `Ctrl+X`, затем `a`), затем `poster-manager`.
- Быстрый цикл: `Shift+Tab` переключает агента в текущей сессии.
- Из CLI: `opencode run --agent poster-manager "<задание>"`.

## Правила работы

- Максимум два подагента одновременно; в общей рабочей директории пишет
  только один `poster-developer`.
- Каждый этап имеет границы, зависимости и критерии приёмки.
- Полные успешные логи тестов не пересылаются: только итоговая строка.
- После этапа менеджер дописывает запись в
  `Poster/docs/agent_team/state.md`.
- Push делает менеджер после зелёных проверок; разработчик и остальные
  подагенты ветку не отправляют.
- `.env`, `secrets/`, ключи, реальная `Poster/post_bot.db` и резервные копии
  защищены правилами прав и не читаются агентами.
- Работающий Telegram-бот не перезапускается и не останавливается агентами.

Ограничения по бюджету и числу шагов — правила координации, а не
технические стоп-лимиты. Точного баланса RouterAI у менеджера нет.
