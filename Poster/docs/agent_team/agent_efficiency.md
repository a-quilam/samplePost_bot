# Эффективность подагентов Poster

Эксперимент (задание владельца, 2026-10-28): компактная статистика работы
подагентов для управления лимитами `steps`. Не телеметрия — записи по
завершённым задачам. Количество шагов OpenCode в отчётах подагентов не
сообщает: в колонке «Шаги» — «недоступно», если данных нет.

## Наблюдения

- До удвоения каждое существенное задание developer/tester упиралось в лимит
  и требовало 1–2 продолжений; продолжения несли повторное чтение кода
  (контекст терялся между вызовами частично).
- После удвоения R2a (сопоставимый объём с R1) завершён одним вызовом без
  продолжений — главный признак, что удвоение снижает суммарный расход,
  а не увеличивает его.
- R2b показал обратное для крупных реализаций: разработчик дважды упирался
  в 160 при задачах «исследование+код+тесты». Крупные этапы лучше резать:
  код отдельно, тесты отдельно.
- Reviewer стабильно исчерпывает лимит на построчном чтении diff (и при 60,
  и при 120), но вердикт даёт. Повторные вызовы почти не добавляют ценности —
  первая попытка была самой полной. Причина, вероятно, в объёме diff этапа,
  а не в лимите как таковой.
- Повторные исследования — основная потеря: продолжение заново читало diff
  и файлы. Сокращается с ростом лимита.
- Тестировщик тратит много шагов на ручные пробы до написания файла; файл
  не сохраняется при исчерпании лимита. Лучше: сначала сохранить скелет
  файла, потом пробы.
- Данных по токенам/стоимости OpenCode не сообщает — недоступно.
