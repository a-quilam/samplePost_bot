# Poster — Telegram-бот подготовки и согласования постов

Бот помогает подготовить пост (событие, афиша), прогнать его через
согласование и опубликовать в канал — без копий черновиков и ручного
переноса текста.

## Как это работает

```
Автор                       Чат согласования                Ответственный        Канал
  │  /create_post ──►         │                                │                   │
  │  диалог полей + фото      │                                │                   │
  │  превью ──────────────►   │ «Новый пост для согласования»  │                   │
  │  сохранить/отправить      │ + кнопки «Выберите ответственного»                │
  │                           │ ──────────────────────────►    │ уведомление       │
  │                           │                                │ «Согласовать» /   │
  │                           │                                │ «Отклонить»       │
  │                           │ ◄────────────────────────────── │                   │
  │  правки при отказе        │                                │ «Опубликовать» ───┼──► публикация
```

* **Превью идентично публикации** — формат собирает один и тот же код
  (`send_post`), поэтому в канале не бывает «сюрпризов».
* **Без дублирования черновиков**: создание/редактирование работает
  с одной записью `drafts`; отклонённый пост отправляется на согласование
  заново тем же черновиком.
* **Медиа-группы** переносятся по `file_id` — файлы не скачиваются.

## Роли

| Роль | Права |
|------|-------|
| Любой пользователь | создание/редактирование своих черновиков (`/create_post`, `/drafts`) |
| Администратор (`ADMIN_IDS`) | `/add_responsible`, `/remove_responsible`, назначение ответственного в чате согласования |
| Ответственный | согласование, отклонение, публикация назначенного поста |

## Стек

* Python 3.13, [python-telegram-bot](https://python-telegram-bot.org) 21–22
  (асинхронный API, `ConversationHandler`, `JobQueue`),
* SQLAlchemy 2.0 (typed `Mapped[]`), SQLite (WAL, busy timeout),
* Развёртывание: локально или Docker (`Dockerfile`, `docker-compose.yml`),
* Качество: ruff, black, mypy, `unittest` (без внешних сервисов).

## Быстрый старт (локально)

```bash
cd Poster
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env       # и заполнить TELEGRAM_BOT_TOKEN, ADMIN_IDS,
                           # REVIEW_CHAT_ID, PUBLICATION_CHAT_ID

python bot.py
```

Запуск бота идёт long polling; для выхода — Ctrl+C.

## Конфигурация (`.env`)

См. [.env.example](.env.example) — файл описывает каждую переменную.
Обязательны `TELEGRAM_BOT_TOKEN` и `ADMIN_IDS`; без `REVIEW_CHAT_ID`
отправка на согласование отвечает подсказкой, без `PUBLICATION_CHAT_ID`
кнопка «Опубликовать» сообщает, что публикация не настроена (бот не падает).

## Docker

```bash
cd Poster
docker compose up --build
```

База данных и логи хранятся в именованных томах, `.env` монтируется
только на чтение (в образ не попадает — проверяется тестами).

## Проверки

```bash
pip install -r requirements-dev.txt
make check          # ruff + black + mypy + тесты
```

Или по отдельности (из каталога `Poster`):

```bash

```

## Команды бота

| Команда | Назначение |
|---------|-----------|
| `/start` | главное меню |
| `/create_post` | создать пост (диалог) |
| `/drafts` | список черновиков (постранично) |
| `/cancel` | отменить текущий диалог |
| `/help` | справка |
| `/add_responsible <Имя> <Telegram_ID>` | добавить ответственного (админ) |
| `/remove_responsible <Telegram_ID>` | удалить ответственного (админ) |

## База данных и миграции

* SQLite-файл (`post_bot.db`, путь задаётся `DATABASE_URL`); при
  подключении выставляются `journal_mode=WAL`, `synchronous=NORMAL`
  и busy timeout — обработчики и фоновые задачи работают параллельно.
* Новые колонки добавляются идемпотентной функцией `_migrate()`
  (см. `database.py`) — `create_all` не изменяет существующие таблицы.
* Фоновая задача раз в сутки удаляет черновики старше 30 дней; посты
  с активным согласованием (`assigned`/`approved`) не удаляются.
* База данных не хранится в git; при локальной разработке она создаётся
  автоматически при первом запуске.

## Логи

`logs/bot.log` — ротация 5 МБ × 5 копий, уровень через `LOG_LEVEL`.
Токен в логи не попадает (уровень httpx принудительно `WARNING`,
см. `log_config.py`).

## Структура кода

```
bot.py                  сборка приложения и обработчиков, запуск
config.py               чтение .env (валидация при импорте)
database.py             engine, PRAGMA, миграции
models.py               SQLAlchemy-модели (Draft, ResponsiblePerson, PostApproval)
approval.py             ядро согласования (статусы, назначение, публикация) — без telegram
errors.py               глобальный обработчик ошибок (лог + ответ пользователю)
handlers/
  post_creation.py      диалог создания/редактирования поста (ConversationHandler)
  approval.py           callback-кнопки согласования и публикации
  drafts.py             список черновиков (пагинация), удаление, листание
  main_menu.py          /start, /help, /drafts, клавиатура главного меню
  admin.py              административные команды
  callbacks.py          возврат в главное меню из inline-кнопок
  jobs.py               фоновые задачи (очистка старых черновиков)
utils/                  форматирование MarkdownV2, валидаторы, typed-хелперы PTB
tests/                  юнит-тесты (unittest, БД в памяти)
```
